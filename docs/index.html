FlyRank Machine Learning Internship Capstone

Ranking Webpages for Next-Month Click Decline

An honest comparison of a CTR baseline and Logistic Regression for prioritizing webpages for content review.

Author: Suhail Ahmed

Lane: Refresh / Content Opportunity Scoring

Abstract

This capstone examines whether February search and engagement signals can help prioritize webpages that later experience lower average daily clicks in March.

The analysis uses 23,703 webpages from 19 anonymized clients. Six February-only features were evaluated using a client-grouped holdout, ensuring that all four test clients were unseen during model training.

A simple February click-through rate baseline was compared with Logistic Regression. Both methods achieved 100% Precision@20 and 98% Precision@50. The CTR baseline achieved slightly higher average precision: 0.8755 compared with 0.8619 for Logistic Regression.

The simpler CTR baseline performed slightly better than the machine-learning model. Therefore, the final recommendation queue uses February CTR as its ranking signal.

The final output is a ranked decision-support queue with warnings for low-volume pages where CTR may be unstable. The results are observational and specific to this dataset, validation split and the February-to-March 2026 period.

Problem Statement

Content teams may manage thousands of webpages but have limited time for manual review. They need a practical way to identify which pages deserve attention first.

Can February search and engagement signals help rank webpages that are likely to experience lower average daily clicks in March?

The goal of this project is not to automatically decide that a page must be refreshed, deleted or rewritten.

Instead, the project creates a ranked review queue that helps content teams investigate potentially declining pages more efficiently.

Decision supported

The output supports a simple operational decision: which webpages should a content team review first?

Unit of analysis

Each row represents one anonymized webpage belonging to one anonymized client.

Target

The binary target records whether a webpage had lower average daily clicks in March 2026 than in February 2026.

A target value of 1 means that average daily clicks declined. A target value of 0 means that they stayed the same or increased.

Dataset and Time Windows

This project uses anonymized webpage performance data from the FlyRank internship warehouse.

The analysis began with 23,742 webpage records. After removing rows that could not be used safely for modelling, 23,703 rows remained.

Feature window

Only February 2026 information was used as model input.

The six features were:

  • Average daily impressions
  • Average daily clicks
  • Average search position
  • Average daily sessions
  • Engagement rate
  • Click-through rate

Outcome window

March 2026 data was used only to create the later outcome label.

A webpage was labelled as a decline when its March average daily clicks were lower than its February average daily clicks.

Privacy protection

The analysis uses anonymized client and content identifiers. No client names, domains, private queries, access tokens or raw warehouse exports are published.

Methods

Baseline

The baseline ranks webpages from highest to lowest February click-through rate.

This provides a simple and interpretable benchmark that the machine-learning model must outperform.

Machine-learning model

Logistic Regression was selected because it is suitable for binary classification and its feature coefficients can be interpreted.

The six February features were standardized before training so that differences in feature scale did not dominate the model.

Evaluation metrics

The project focuses on ranking quality because the practical goal is to identify which webpages should be reviewed first.

  • Precision@20: the percentage of actual declines among the 20 highest-ranked webpages.
  • Precision@50: the percentage of actual declines among the 50 highest-ranked webpages.
  • Average Precision: ranking quality across the full precision-recall curve.

Model comparison

The CTR baseline and Logistic Regression were evaluated on exactly the same unseen test rows using the same metrics.

The simpler baseline was preferred when the machine-learning model did not produce a measurable improvement.

Validation and Leakage Controls

Client-grouped holdout

The data was split by client rather than by individual webpage.

This prevented webpages from the same client appearing in both the training and test sets.

15 Training clients
4 Unseen test clients
0 Client overlap
1,671 Test webpages

The training set contained 22,032 webpages, while the test set contained 1,671 webpages from four completely unseen clients.

Time-based leakage prevention

All model features came from February 2026.

March information was used only to create the later decline label and was not included as a model feature.

Identifier leakage prevention

Client and content identifiers were retained only for grouping, auditing and displaying anonymized results.

They were not used as predictive features.

Missing-value check

The final modelling dataset contained no missing values across the six selected features.

Reproducibility

A fixed random seed of 42 was used for the grouped split and model training.

The final audit confirmed zero client overlap, February-only features, no missing model values and identical test rows for both methods.

The test set had a decline base rate of 23.22%. This means that without useful ranking information, approximately 23 out of every 100 test webpages would be expected to decline.

Logistic Regression did not outperform the simpler CTR baseline. Its average precision was 0.0136 lower.

Feature evidence

February CTR had the largest positive Logistic Regression coefficient, making it the strongest ranking signal among the six selected features.

When CTR was removed, model average precision fell from 0.8619 to 0.4231. This shows that the model depended heavily on CTR rather than discovering several equally strong signals.

Error analysis

At a classification threshold of 0.50, the model produced:

  • 1,252 true negatives
  • 172 true positives
  • 31 false positives
  • 216 false negatives

Reviewing individual errors showed that low-volume pages can receive high scores because a small number of clicks can create a large CTR. This finding informed the warning labels used in the final review queue.

Interpretation

The result does not show that high CTR causes future click decline. It only shows that February CTR was a strong ranking signal in this specific grouped holdout and time period.

Recommended review workflow

  1. Check whether the page has enough impressions and clicks for a stable CTR.
  2. Review its recent traffic and ranking trend.
  3. Check for seasonality or changes in search demand.
  4. Inspect content freshness, relevance and technical issues.
  5. Compare the page with competing or overlapping content.
  6. Choose monitoring, updating or no action after human review.

Intended use

The queue helps a content team decide which webpages to investigate first. It does not automatically determine that a page should be rewritten, deleted or refreshed.

Limitations

Limited time window

The analysis uses February 2026 features and a March 2026 outcome. Performance may differ during other months because of seasonality, changing search demand or unusual traffic patterns.

Limited unseen clients

The test set contained four unseen clients. This supports honest validation, but it is not enough to claim that the same performance will occur for every client.

Single grouped split

The results come from one client-grouped holdout. Future work should repeat the analysis across multiple grouped splits to measure result stability.

Strong dependence on CTR

Logistic Regression relied heavily on February CTR. Removing CTR reduced average precision from 0.8619 to 0.4231.

Low-volume instability

Many top-ranked webpages had very low impressions and clicks. A small number of clicks can create an unusually high CTR.

A production workflow should include a minimum-volume rule or an uncertainty warning.

Binary target limitation

The target only records whether March average daily clicks were lower than February average daily clicks.

It does not measure:

  • The size of the decline
  • Whether the decline was temporary
  • Whether seasonality caused the decline
  • Whether the page actually required a content update

No causal claim

The analysis identifies predictive relationships. It does not prove that high CTR causes future decline or that refreshing a flagged page will improve performance.

The results should be used as decision support for human review, not as an automatic content-refresh system.
